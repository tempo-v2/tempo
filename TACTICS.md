# Tempo V2 tactics

The local Tactics page uses the shared Tempo Board, orthodox chess legality in
Rust, and a separate SQLite practice database. Select or drag a piece to a
highlighted square. The board shows each accepted move and its reply. A legal
move outside the source solution records Again and shows a correction arrow
on the same position. A clean solve records Good. When a puzzle is complete,
a check mark appears briefly before the next puzzle loads.

## Build and open

From the assembled workspace root, using Rust 1.85+ and Node 22.13+:

```sh
(cd tempo-core-components && npm ci && npm run build)
(cd tempo/ui && npm ci --install-links && npm run build)
make start
```

If your existing root Makefile lacks the target, add `include tempo/tools/local.mk`
after your existing targets or run `make -f tempo/tools/local.mk start` from the
workspace root.

Set `TEMPO_DB` or `TEMPO_PORT` on the make command to use another existing
practice database or port. `make start` rebuilds Tempo and replaces this
checkout’s running Tempo servers across all ports. Press Ctrl+C to stop the
new server.

Open [Tempo Tactics](http://127.0.0.1:41821). Use the exact URL the server
prints. The server binds to IPv4 loopback and opens the existing practice
database without reseeding it. Reloading a tab resumes its last displayed
attempt, including a completed board. If a move reply went missing, the same
tab replays the saved intent before it offers another action.

The browser imports the built Core package through its public JavaScript and
CSS exports. Rebuild Core and reinstall the local app dependency when changing
Core. See [UI source and recovery](ui/README.md) and the Core README in the
adjacent repository for usage and licensing.

## Import a fresh practice database

Use a private working directory outside `tempo/ui/dist`. Keep Tempo 1 exports
and import reports in that location. A normalized batch is generated by
[the transfer tools](tools/tactics/README.md).

```sh
umask 077
mkdir -p .local/tactics-mvp
target/debug/tempo init-practice .local/tactics-mvp/new-practice.sqlite
target/debug/tempo import-tactics .local/tactics-mvp/new-practice.sqlite \
  .local/tactics-mvp/personal-transfer-v2/normalized.json \
  > .local/tactics-mvp/new-import-mapping.json
python3 tempo/tools/tactics/reconcile.py \
  .local/tactics-mvp/personal-transfer-v2/manifest.json \
  .local/tactics-mvp/new-import-mapping.json \
  > .local/tactics-mvp/new-source-to-target.json
```

For packaged-only practice, run the pack converter against the pinned Tempo 1
checkout and import into a different database.

```sh
python3 tempo/tools/tactics/convert.py packaged \
  --legacy-repo /path/to/tempo-1 \
  --pack mateIn2-focused-04 \
  --output .local/tactics-mvp/pack-sample
target/debug/tempo init-practice .local/tactics-mvp/pack-practice.sqlite
target/debug/tempo import-tactics .local/tactics-mvp/pack-practice.sqlite \
  .local/tactics-mvp/pack-sample/normalized.json \
  > .local/tactics-mvp/pack-import-mapping.json
```

Import validates the whole normalized batch before writing. Use the conversion
manifest for invalid or excluded source records and the import report for
retained targets and quarantines. Reimporting an unchanged batch keeps the
dataset, content versions and learning. A source ID associated with different
content fails the transfer before publication.

This release uses StableQueue, StandardLearning, and the three-day Good,
next-day Again fixed-interval scheduler with UTC study days. An eligible
same-day repeat uses StandardLearning's existing credit rules. The practice
database starts with fresh V2 schedules. The server-side raw export preserves
Tempo 1 reviews and scheduling payloads separately. A historical FSRS-state
mapping and browser-only history transfer remain open.

## Verify

```sh
cargo test -p tempo-chess -p tempo
python3 .planning/scripts/check_architecture.py .
node --test tempo/tests/ui_imports.mjs tempo/tests/ui_boundary.mjs tempo/tests/tactics_http.mjs
```

The HTTP test needs permission to bind and connect to loopback. It imports an
existing Tempo puzzle into a disposable file, discards a committed reply,
reopens SQLite in a restarted server and reconstructs the browser controller.
A separate real-browser run exercises the rendered board.
